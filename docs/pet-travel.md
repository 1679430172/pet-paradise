# 宠物旅行部署与验证

学生入口：导航「旅行」，路径 `/#/travel`。

老师代旅行：普通视图点击宠物打开装扮弹窗，再点击顶部「管理旅行」，选择目的地并确认消耗学生 1 张券。弹窗显示当前宠物的旅行状态、剩余时间，归来后可代领行李。无券时提供前往学生奖励页的入口。进入页面、打开弹窗、重新切回页面及代操作后刷新，不轮询数据库。满级后的领养入口也位于装扮弹窗。

已有数据库在旅行券和统一收支迁移之后执行 `supabase-migration-teacher-travel.sql`。老师只能操作本班学生；代出发/代领取复用学生端的扣券和结算事务，并保存 `started_by` / `claimed_by`。统一收支记录将代出发标为对应老师，学生端和老师端共享同一趟旅行及奖励。`scripts/test-teacher-travel.mjs` 验证权限、重试、并发、归属与操作人；浏览器脚本包含老师代出发、手机确认及代领取流程。

教师学生详情统一展示「收支记录」，按时间倒序合并任务奖励、其他积分奖励、喂养、商城购买、旅行用券和奖励撤销。收入显示正号，支出显示负号；同时奖励积分和券只占一条记录。每页 10 条，顶部显示积分和旅行券余额。撤销保留原获取记录，并追加一条扣回记录。

已有数据库在旅行券迁移后执行 `supabase-migration-student-ledger.sql`，再发布前端；该迁移直接读取业务流水，不依赖之前的分开展示查询，也不会再次扣分或扣券。全新安装 SQL 已包含。早期未保存的流水无法还原，未记录的历史余额不会推算显示。
## 本期规则

- 森林营地 4 小时、贝壳海湾 8 小时、星光山谷 12 小时。
- 老师创建或编辑任务时设置奖励积分、旅行券，或同时奖励两者；至少一项大于 0。
- 每次出发消耗 1 张旅行券，取消每日免费次数和每日出发上限；同一学生的不同宠物可以同时旅行，每只宠物只能有一段未领取的旅行。
- 旅行券由老师确认任务完成后发放，支持单人和批量发奖。券可积攒、不失效。
- 任务奖励记录保留当次积分和券数快照；撤销时一并收回，任一余额不足则整笔不撤销。
- 旅行期间不可喂养，饱食度暂停消耗，按预定归来时间恢复（不必先领行李）；老师可以继续加分；关掉页面不影响计时，归来奖励不过期。
- 每次保底一张当地随机明信片和 1 枚印章，共 9 种明信片。
- 1% 概率获得目的地专属装扮，两款各 0.5%。已拥有的装扮额外转为 2 枚印章。
- 每件装扮用 8 枚印章兑换；印章独立于积分，不参与排行榜或成长。
- 6 件专属装扮沿用商城装备入口；已拥有的装扮也支持老师代装备。
- 旅行收藏永久保留；页面展示最近 20 次旅行记录，明信片相册汇总全部旅行。

## 部署

已启用旅行的数据库，在目标 Supabase SQL Editor 执行 `supabase-migration-travel-tickets.sql`，再发布前端。未启用旅行的数据库需先确保已执行课堂、商城和旅行迁移，最后执行旅行券迁移。全新安装使用已包含这些迁移的 `supabase-schema.sql`。

迁移可重复执行，但顺序必须保持：课堂 → 商城 → 旅行 → 旅行券。不要在旅行券迁移之后单独重跑旧旅行迁移；如需重跑，最后再次执行旅行券迁移。

既有任务默认奖励 0 张券，既有学生默认持有 0 张券，不自动补发。已出发的免费旅行继续有效，不补扣券。历史旅行、装扮和印章保留。历史任务奖励也不会因后来编辑任务而补发券。

迁移新增四张表和四个 RPC，增加 `shop_items.acquisition`，允许 `user_items.order_id` 为空，以区分旅行获得与商城购买。现有购买记录保留。专属装扮不能通过学生购买或老师代购接口买到。

迁移后检查：

```sql
SELECT id, name, hours FROM travel_destinations ORDER BY sort_order;
SELECT i.name, i.category, r.destination_id, r.stamp_cost
FROM travel_rewards r JOIN shop_items i ON i.id = r.item_id;
```

应返回 3 个目的地、6 个奖励。使用测试学生完成出发、归来领取、兑换、装备流程；不要修改真实学生旅行时间来加速验收。

## 验证脚本

`scripts/test-travel-db.mjs` 验证旅行基础迁移（含旧每日规则）及全新建库。`scripts/test-travel-tickets-db.mjs` 验证当前旅行券规则：任务奖励组合、奖励快照、发券与扣券幂等、同日多次旅行、余额不足、撤销和事务回滚。测试使用独立 PGlite 数据库，不连接线上。

`scripts/test-travel-ui.mjs` 使用本地 Vue 页面、Playwright 和 PGlite RPC 适配器，验证 1440/768/390/320 宽度、无券拦截、任务发券、出发扣券、刷新、修改客户端时间、领取响应丢失重试、商城装备、印章兑换、缺失迁移及恢复、教师创建券任务和编辑混合奖励。它是本地集成测试，不代表线上数据库验收。

运行依赖 `@electric-sql/pglite` 与 `playwright`。可通过 `PGLITE_MODULE`、`PLAYWRIGHT_MODULE` 指向外部模块入口，无需修改项目依赖。UI 测试先启动 Vite；默认地址 `http://127.0.0.1:5193`，可用 `APP_URL` 覆盖；`ARTIFACT_DIR` 指定截图目录。

## 身份模型边界

本功能沿用项目现有自定义账号模式：RPC 接收学生 ID，校验学生角色及宠物归属。项目没有 Supabase Auth 会话绑定，因此这里的归属校验不等于证明调用方就是该学生；账号身份防冒用需要在独立认证改造中统一处理。旅行表没有客户端直接读写权限，奖励、时间、限次和印章由服务端事务控制。

多宠物独立旅行：在老师代旅行迁移之后执行 `supabase-migration-per-pet-travel.sql`。旅行券和装扮收藏仍归学生共享；每只宠物单独出发、计时、领奖。

独立明信片赠送：执行 `supabase-migration-postcard-unlocks.sql` 后，数据库管理员可向 `travel_postcard_unlocks` 写入指定学生、目的地和已有故事。不影响旅行记录、印章或旅行券。

明信片扩充：执行 `supabase-migration-more-postcards.sql`，为森林、海湾、山谷各追加 9 张，共 36 张。保留原故事与已有收藏，重复执行不会重复追加；每次旅行仍随机带回一张，新增故事自动加入抽取范围。

宠物来源快照：在上述迁移之后执行 `supabase-migration-postcard-pet-snapshots.sql`。出发时保存宠物 ID、名字、种类、等级和形态，领奖或宠物改名、升级不会更改快照。不同旅行保留各自来信版本，故事收集进度按目的地与故事去重计算。手动赠送显示为纪念版；旧旅行未记录的形态保持未知，不用当前宠物状态补写。此迁移已在本地数据库测试，尚未应用到远程数据库。

相册最终采用 36 张纯场景插画，不拼接宠物角色；有来源信息时以文字落款展示。只保留目的地筛选。插画与生成提示词见 `docs/travel-art.md`。

旅行照顾规则：已有数据库最后执行 `supabase-migration-travel-care.sql`，再发布前端。出发时结算此前的饱食度消耗，旅行时冻结，归来后只计算归来以来的消耗；单只、批量、学生端和直接 RPC 均受约束。迁移会兼容正在旅行的宠物，重复执行不会重复扣值。
