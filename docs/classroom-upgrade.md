# 课堂功能升级

## 奖励撤销升级

已经执行课堂事务迁移的项目，只需再执行 `supabase-migration-revoke-awards.sql`，然后发布前端。新部署初始化脚本已包含它。旧项目尚未升级课堂事务时，先执行课堂迁移，再执行撤销迁移；之后不要单独重跑旧课堂迁移，以免覆盖新的周榜函数。

老师在「总览 → 积分发放记录」逐笔撤销，包括通过普通页或大屏批量发放的各个学生记录。确认弹窗展示学生、任务、原奖励积分，必须填写 1–200 字原因。只能撤销自己发给目前仍属于本班学生的奖励；任务停用不影响纠错。

撤销以原记录 ID 为幂等键，在同一个数据库事务中锁定学生余额和发奖记录、收回原奖励积分、写入撤销时间、操作者及原因。重复操作或响应丢失后的重试不会重复扣分。原发奖记录和收入流水保留，周榜排除已撤销记录对应的收入；总览统计有效发放积分，学生详情也标识已撤销。

余额不足时整笔撤销失败，不允许扣成负数或部分扣除，也不回退宠物成长。此规则意味着已经花掉大部分奖励的学生，需要有足够余额后才能撤销。没有自动撤销整批功能，避免一处误操作影响全班。

沿用现有自定义登录和开放 RLS，操作者参数校验属于业务检查，不是完整身份认证。新增撤销字段的更新策略供 `SECURITY INVOKER` 函数使用。

运行 `node scripts/test-revoke-awards.mjs` 验证事务回滚、重复撤销、原因和归属检查、余额不足、停用任务、榜单和统计、开启 RLS 后的 anon 调用及迁移重跑。原有页面集成脚本也覆盖撤销确认、成功记录、响应丢失重试及余额不足提示。测试均使用隔离 PGlite 数据库，不修改生产数据。

## 部署顺序

1. 在现有项目的 Supabase SQL Editor 执行 `supabase-migration-classroom.sql`。脚本有显式事务，可重复执行，不清空已有数据。
2. 构建并发布这一版前端。已打开的旧页面需要刷新，以免旧客户端继续分步修改余额。
3. 教师进入「宠物 → 课堂大屏」；「排行」查看本周成长榜。先用测试学生核对一次发分、投喂和榜单。

新安装继续使用 `supabase-schema.sql`，其中已包含相同迁移。以后修改喂食规则时，要同步数据库 `feed_pet` 中的经验、饱食衰减和等级阈值，以及前端 `constants.ts`；价格仍从数据库 `settings.action_costs` 读取。

## 喂食及积分写入

- 学生喂食、教师单只/批量代喂都调用 `feed_pet`。数据库先锁定学生余额，再锁定宠物，校验归属、价格和余额，随后一起写入余额、成长和喂食流水。任何一步出错整次回滚。
- 同一学生的多只宠物共用余额锁。数据库使用实际余额计算，前端不再回写自己计算的余额。
- `award_task_points` 将任务完成记录、余额增加和收入流水放在同一事务内，奖励金额以数据库的有效任务为准。
- `publish_diary` 将日记、每日首篇奖励和流水放在同一事务内；每天的界线是北京时间 00:00。删除已奖励日记也不能再次领取当天奖励。
- 保持既有规则：饱食度满也能喂，只有喂食增加经验。点赞和日记不再进行零经验的宠物回写，避免覆盖并发喂食结果。
- 一次操作生成固定请求编号。传输异常最多自动重试一次，复用同一编号；重复请求不会重复扣分或发奖。两次传输都失败时仍可能无法判断服务器结果，界面提示后应刷新确认再发起新的操作。
- 批量操作按学生/宠物逐项提交，单项失败不会撤销已成功项。大屏保留失败学生的选择并展示名单和原因。

这些函数为 `SECURITY INVOKER`，延续项目原有自定义登录与开放 RLS，actor 参数只做业务归属校验。此变更没有将现有认证替换成 Supabase Auth，也不能防止持有公开接口的调用者伪造 actor；完整身份与权限治理仍是独立工作。

## 排行榜口径

- 按数据库时间计算北京时间本周一 00:00（包含）至下周一 00:00（不包含）。每次进入或手动刷新时重新计算，不设置定时刷新。
- 累加 `point_earnings` 中学生在当前班级获得的正积分；消费不计入，不按余额排序。同分并列，无收入显示横线。
- 不再只取余额最高的 50 人，也不逐个请求宠物信息；一次数据库查询返回全班榜单与每人的最高等级宠物。
- 升级时按 `task_completions` 中记录的历史奖励补入流水，请求/来源编号防止迁移重跑重复统计。
- 历史日记没有奖励流水，无法准确重建当时的奖励金额，**不补算历史日记积分**；迁移后经新前端发布的日记奖励才计入。已有余额保留，但不作为本周收入。

## 课堂大屏

教师宠物页的「课堂大屏」按钮切换到宽屏布局，隐藏侧边导航。「全屏显示」进入浏览器全屏，Esc 可退出浏览器全屏；「返回普通视图」恢复原页面导航。

支持学生姓名搜索、原有排序、紧凑/标准/大字卡片、选择当前筛选结果、快捷发放本班有效任务奖励。没有领养宠物的学生也可获奖。发奖成功在卡片显示任务和积分，宠物跳动；升级展示学生姓名与宠物。无额外宠物经验奖励，不定时刷新页面。

## 验证

`node scripts/test-classroom-db.mjs` 在独立 PGlite PostgreSQL WASM 数据库运行真实迁移：失败回滚、重复请求、归属检查、余额不足、满饱食度、每日奖励、周边界、同分和超过 50 人统计、迁移重复执行与 anon 调用。

`node scripts/test-classroom-ui.mjs` 需要运行中的本地应用（默认 `http://127.0.0.1:5193/`）。使用实际 Vue 页面，在 Playwright 测试拦截层把 REST 请求送入隔离 PGlite 数据库；不连接生产数据。覆盖选择发奖、部分失败、未领养学生奖励、服务器已提交但响应丢失后的喂食重试、全屏、移动布局、导航恢复和缺少迁移的报错。截图输出默认 `classroom-verification.local/`。

测试依赖可安装在独立临时目录，不影响产品依赖：`@electric-sql/pglite`、`playwright`，以及可运行的 Chrome。也可以通过环境变量指定现成模块路径：`PGLITE_MODULE` 指向 PGlite `dist/index.js`，`PLAYWRIGHT_MODULE` 指向 Playwright `index.mjs`；`BROWSER_CHANNEL` 默认 `chrome`，`APP_URL` 和 `ARTIFACT_DIR` 可覆盖默认地址及输出位置。

这些测试验证本地真实 SQL 和页面集成。PGlite 不替代生产 PostgreSQL 多连接并发测试；线上迁移、网络权限及最终上线验收需在目标环境执行。
